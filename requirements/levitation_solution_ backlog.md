# **Бэклог проекта: Levitation Solution (Phase 4\)**

Данный документ содержит атомарные задачи (Эпики) для разработки программного обеспечения Базы и Агента в рамках Фазы 4\. Для каждой задачи определены требования к модульному тестированию (Unit Tests) для обеспечения надежности кода перед заливкой на реальное «железо».

## **💻 УЗЕЛ 1: СОПРОЦЕССОР БАЗЫ (RP2040-Zero) — Язык: C/C++**

### **LS-1: Разработка генератора высокочастотного аппаратного ШИМ (PWM)**

> * **Основная цель задачи:** Настроить микроконтроллер RP2040-Zero на генерацию 5 независимых каналов аппаратного ШИМ-сигнала для управления драйверами TC4427.  
> * **Стек:** C/C++ (PlatformIO / Arduino IDE), RP2040 Hardware PWM API, Unity (для тестов).  
> * **Подробности:** Микроконтроллер должен выступать «единым генератором частоты». Необходимо настроить 5 пинов (GPIO) на выдачу ШИМ с частотой строго выше 20 кГц. Сигналы должны иметь возможность менять скважность (Duty Cycle) от 0 до 100% с шагом не менее 10-бит (0-1023).  
> * **Критерии приемки (DoD):** Код компилируется; осциллограф подтверждает частоту \>20 кГц; скважность меняется без перезагрузок таймера.  
> * **Модульные тесты (Unit Tests):**  
  * Написать тест, проверяющий, что функция установки скважности (set\_pwm\_duty) не принимает значения выходящие за пределы 0-1023 (Boundary Testing).  
  * Использовать mock-объекты регистров таймера RP2040 для проверки правильности записи делителя частоты (чтобы программно убедиться, что частота инициализируется именно на \>20 кГц).

### **LS-2: Реализация высокоскоростного протокола связи (RP2040 \<-\> RPi 5\)**

> * **Основная цель задачи:** Написать парсер данных для приема «целевого вектора» от Raspberry Pi 5\.  
> * **Стек:** C/C++, UART или SPI библиотека.  
> * **Подробности:** RP2040 слушает входящий порт (UART/SPI). RPi 5 присылает массив из 5 чисел (скважность). Код мгновенно парсит пакет и передает значения в PWM-контроллер (LS-1).  
> * **Критерии приемки (DoD):** Реализован буфер приема; защита от «битых» пакетов; задержка парсинга \< 1 мс.  
> * **Модульные тесты (Unit Tests):**  
  * Тест парсера на «идеальный» пакет данных (успешное извлечение 5 значений).  
  * Тест парсера на битые/обрезанные пакеты (должен отбрасывать мусор и не приводить к крашу памяти/буфера).  
  * Тест проверки контрольной суммы (CRC/Checksum) пакета.

## **💻 УЗЕЛ 2: АГЕНТ / СФЕРА (ESP32-CAM) — Язык: C/C++**

### **LS-3: Интеграция аппаратного Sensor Fusion (BNO085)**

> * **Основная цель задачи:** Настроить чтение готовых кватернионов с чипа BNO085 по шине I2C.  
> * **Стек:** C/C++, I2C, библиотека Adafruit\_BNO08x.  
> * **Подробности:** Считывать углы Эйлера (Pitch, Roll, Yaw) или кватернионы с частотой не менее 100 Гц без перегрузки ядра ESP32.  
> * **Критерии приемки (DoD):** Успешная инициализация I2C; чтение без зависаний (Clock Stretching handled); вывод в Serial.  
> * **Модульные тесты (Unit Tests):**  
  * Mock-тестирование I2C интерфейса: подать сырой байтовый массив, имитирующий ответ BNO085, и проверить, что математика ESP32 верно переводит его в Float значения углов.  
  * Тест на Time-out: искусственно сымитировать зависание шины I2C и проверить, что код корректно восстанавливается (reset I2C), а не уходит в вечный цикл (Watchdog Timeout).

### **LS-4: Разработка логики «Впрыска тока» (Smart DC-Coil)**

> * **Основная цель задачи:** Написать функцию управления силовым MOSFET D4184 внутри Агента.  
> * **Стек:** C/C++, ESP32 LEDC PWM.  
> * **Подробности:** На основе данных наклона выдавать ШИМ-импульс на затвор транзистора, дозируя ток в 60-мм катушку.  
> * **Критерии приемки (DoD):** Наличие программного лимита времени импульса (защита от плавления); плавное управление.  
> * **Модульные тесты (Unit Tests):**  
  * Unit-тест программного ограничителя (Software Fuse): вызвать функцию подачи максимального тока, программно подождать 500 мс и убедиться, что внутренний таймер автоматически сбрасывает ШИМ в 0\.  
  * Тест логики активации: проверить, что при нулевом отклонении сферы (в идеальном покое) функция впрыска выдает Duty Cycle \= 0\.

## **💻 УЗЕЛ 3: МОЗГ И ЛОГИКА (Raspberry Pi 5\) — Язык: Python**

### **LS-5: Написание драйвера опроса ближнего поля (ADS1115 \+ Холлы)**

> * **Основная цель задачи:** Обеспечить чтение данных с 4 датчиков Холла SS49E через АЦП на максимальной скорости.  
> * **Стек:** Python 3, \`pytest\`, \`smbus2\` (или \`adafruit-circuitpython-ads1x15\`).  
> * **Подробности:** Настроить ADS1115 на 860 SPS. Читать напряжения с 4 каналов и переводить в дистанцию/силу поля.  
> * **Критерии приемки (DoD):** Вывод массива из 4 значений; отсутствие блокировок; асинхронный опрос.  
> * **Модульные тесты (Unit Tests):**  
  * \`pytest\` с использованием \`unittest.mock\`: подменить шину I2C и передать фиктивные 16-битные значения. Проверить, что метод перевода \`voltage\_to\_distance()\` возвращает правильные миллиметры по заданному полиному.  
  * Тест на отрицательные/аномальные значения (если магнитное поле перевернуто, код не должен падать с математической ошибкой).

### **LS-6: Интеграция оптической ToF-матрицы и Трансляция Координат**

> * **Основная цель задачи:** Получение 3D-вектора с датчика VL53L5CX и компенсация его смещения.  
> * **Стек:** Python 3, \`pytest\`, драйвер VL53L5CX.  
> * **Подробности:** Считывать матрицу 8x8. Находить точку минимума. Применять \`OFFSET\_X\_MM \= 15.0\` для перевода в абсолютные координаты Базы.  
> * **Критерии приемки (DoD):** Опрос 64 зон (15-60 Гц); корректный возврат XYZ координат.  
> * **Модульные тесты (Unit Tests):**  
  * Передать в функцию сглаживания mock-массив 8x8, где искусственно задана «яма» в координате (2,3). Тест должен проверить, правильно ли алгоритм находит этот минимум.  
  * Тест математической трансляции: подать на вход (X=20, Y=5) и проверить, что на выходе получается (X=5, Y=5) с учетом \`OFFSET\_X\_MM \= 15.0\`.

### **LS-7: Архитектура ПИД-регулятора и Комплементарного фильтра (Core Loop)**

> * **Основная цель задачи:** Свести данные сенсоров, вычислить ошибку и отправить команду на RP2040.  
> * **Стек:** Python 3, \`pytest\`, \`simple-pid\`.  
> * **Подробности:** Sensor Fusion (до 5 см — Холлы, выше — ToF) \-\> ПИД по осям XYZ \-\> Трансляция в 5 значений ШИМ \-\> Отправка пакета.  
> * **Критерии приемки (DoD):** Главный цикл не блокируется; возможность изменения коэффициентов P, I, D на лету.  
> * **Модульные тесты (Unit Tests):**  
  * Тест Комплементарного фильтра (Boundary Testing): передать высоту Z=4.9 см (ожидается 100% доверие Холлам) и высоту Z=6.1 см (ожидается 100% доверие ToF). Проверить выходные веса фильтра.  
  * Тест ПИД-контура: подать фиксированную ошибку \`Error \= 10\` и проверить, что выходы P, I, D вычисляются корректно по заданной математической формуле.  
  * Тест формирования UART-пакета (проверка, что 5 значений ШИМ правильно упаковываются в байты перед отправкой на RP2040).
