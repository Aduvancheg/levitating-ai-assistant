# Спецификация физических сценариев и E2E-тестирования (v2.0)
## Use Cases, Dynamic Trajectories & E2E Testing Framework (.docs/use_cases_and_e2e_scenarios-v3.md)

Этот документ представляет собой авторитетный реестр физических сценариев использования (Use Cases) и требований к сквозному (E2E) тестированию левитационного комплекса **Antigravity**. Данный файл является непосредственным API-контрактом для связи между кодовой базой сервера `main_server-v7.py`, интерфейсом пользователя `index_html_template-v7.txt` и авто-тестами качества в Antigravity IDE.

Каждый сценарий представляет собой завершенную поведенческую подпрограмму, которая может быть активирована пользователем в один клик через веб-интерфейс и выполнена асинхронно в рамках ПИД-контура левитации на Raspberry Pi 5.

---

## 1. Глобальная архитектура поведенческой логики и FSM

Поведение системы левитации описывается детерминированным конечным автоматом высокого уровня (High-Level Behavior FSM), выполняющимся в основном цикле Raspberry Pi 5:

```
       ┌────────────────────────────────────────────────────────┐
       │                                                        │
       ▼                                                        │
┌──────────────┐   SMOOTH_TAKEOFF   ┌──────────────┐            │
│   STANDBY    ├───────────────────►│   HOVERING   │            │
│ (На столе,   │                    │ (Зависание на│            │
│  ШИМ = 0)    │◄───────────────────┤ Target Z=25) │            │
└──────┬───────┘    SAFE_LANDING    └──────┬───────┘            │
       │                                   │                    │
       │                                   │                    │
       │ SAFE_SHUTDOWN                     │ Run Scenario       │
       │ (Плавное гашение                  │ (UC-3 .. UC-6)     │
       │  системы до нуля)                 ▼                    │
       ▼                            ┌──────────────┐            │ RTH_ROUTINE
┌──────────────┐                    │ SCENARIO_RUN │────────────┘
│   SECURED    │◄───────────────────┤ (Траектория  │  (По завершению
│ (Безопасное  │   SAFE_SHUTDOWN    │ или реакция) │   или прерыванию)
│ отключение)  │                    └──────────────┘
└──────────────┘
```

## 3. Реестр интерактивных сценариев R&D

### UC-7: Мягкая посадка сферы (SAFE_LANDING)
*   **Описание:** Линейный плавный спуск Агента на поверхность Базы.
*   **Физическая механика:** Линейное уменьшение уставки высоты `Target Z` со скоростью 5 мм/с. По достижении физического стола (Z = 0 мм) силовой ШИМ удерживается на уровне компенсации веса в течение 500 мс (для мягкого успокоения упругого удара), после чего мгновенно обесточивается.
*   **Поведение по завершении:** Сфера остается лежать на столе в состоянии STANDBY (ШИМ = 0).

### UC-9: Безопасное выключение комплекса (SAFE_SHUTDOWN) [NEW v2.0]
*   **Описание:** Комплексный асинхронный процесс подготовки левитатора к аппаратному отключению питания (извлечению вилки 27W), исключающий падение сферы, термический удар катушек и высоковольтные ЭДС-выбросы самоиндукции.
*   **Физическая механика:**
    1.  **Пылевидный спуск (Z-axis Descent):** Линейный спуск уставки `Target Z` от текущей высоты до 0 мм на скорости 5 мм/с (уменьшение `Target Z` на 1.0 мм каждые 200 мс).
    2.  **Затухающее размагничивание (Coils Soft Ramp-down):** Чтобы не допустить высоковольтных импульсов самоиндукции при мгновенном обесточивании медных обмоток катушек (что гарантированно сожгло бы затворы транзисторов AOD4184A), ток катушек плавно экспоненциально или линейно снижается до 0 в течение ровно 2.0 секунд (шаг ШИМ вниз на 5% каждые 100 мс).
    3.  **Изоляция Агента (Agent Sleep):** По беспроводному протоколу Wi-Fi на сферу ESP32-CAM отправляется команда `STANDBY`. Бортовой MOSFET-ключ полностью закрывается, а NC-реле CPC1017N переводится в замкнутое состояние `CONNECTED (Charging)` — безопасное пассивное положение, переводящее Агента в режим пассивного сна/зарядки.
    4.  **Halt & Block:** Бэкенд Raspberry Pi 5 блокирует силовой ключ (устанавливает `bist_unlocked = False`, `bist_bypass_active = False`), отключает все фоновые расчеты ПИД-контура и выставляет на UI глобальный флаг безопасности: `safe_to_unplug = True`.
*   **Поведение по завершении:** Система замирает в заблокированном состоянии SECURED, на весь экран UI выводится зеленое уведомление: **«СИСТЕМУ МОЖНО БЕЗОПАСНО ОТКЛЮЧИТЬ ОТ СЕТИ»**.
*   **Status Pipeline (Шаги):**
    1. `SHUTDOWN-01` (Running) -> Плавный спуск сферы (Z-Descent).
    2. `SHUTDOWN-02` (Pending) -> Пошаговое размагничивание катушек базы (EMF Suppression).
    3. `SHUTDOWN-03` (Pending) -> Перевод сферы Агента в режим парковки и закрытие MOSFET.
    4. `SHUTDOWN-04` (Pending) -> Фиксация и блокировка безопасного отключения.
*   **Критерии физической приемки (DoD):** Спуск проходит без удара. Напряжение на затворах MOSFET базы в конце процесса равно строго 0V. Индукционный выброс самоиндукции на стоке транзисторов не должен превышать 12V (полностью поглощается диодами SS54). Пользователь видит на экране четкий зеленый сигнал готовности к отключению питания.
*   **Сценарий E2E-теста (QA):** Запуск теста в симуляторе. Проверяется, что при вызове `/api/manage/execute` с параметром `SAFE_SHUTDOWN` все 4 шага пайплайна последовательно меняют статусы на `DONE`, `pwm_channels` в конце равны `[0, 0, 0, 0, 0]`, а переменная `safe_to_unplug` переходит в `True`.
\n\n### Физический симулятор ПИД и ЭДС самоиндукции (Lenz Simulation Failsafe) - V3.0
Эмулятор физики движения сферы в pytest дополнен моделью переходных процессов индуктивности:
$$\frac{di}{dt} = \frac{V_{PWM} - i \cdot R}{L}$$
При изменении ШИМ-вектора симулятор замеряет пиковую ЭДС $V_{\text{kick}} = -L \cdot \frac{di}{dt}$. Тестовый сценарий `TEST-8` проверяет, что при прыжках уставки ПИД математический Slew-Rate Limiter (предел 10 единиц за такт) удерживает выбросы напряжения $V_{\text{kick}}$ ниже безопасного порога **0.5V** во всей симуляции, предотвращая виртуальный пробой MOSFET.
