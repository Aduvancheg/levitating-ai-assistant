# Бэклог рефакторинга и интеграции ToF: Конфигурация «Осевая помехозащищенная» (OFFSET = 45.0 мм)
## Реестр задач и системный мастер-промпт для Antigravity IDE // Project Antigravity Phase 4

Этот документ является официальным дополнением к техническому бэклогу проекта **Antigravity** [levitation_solution_backlog_2-v9.md] и фиксирует финальный архитектурный стандарт интеграции оптического ToF-датчика VL53L5CX на сенсорную крышку базы версии v7.0 [enclosure_architecture_v7.md].

## 1. Физико-технический контекст решения (R&D Case Study)

В процессе проектирования крышки базы v5.0 под увеличенные 22-мм катушки **GU22-13** была выявлена критическая пространственная коллизия:
* **Коллизия:** Боковая катушка №2 (East) расположена на радиусе `27.0 мм` [base_power_assembly_guide-v5.md, enclosure_architecture_v7.md]. С учетом радиуса окна под катушку (`11.5 мм`), её физический контур занимает диапазон от +15.5 мм до +38.5 мм по оси X [enclosure_architecture_v7.md]. Расположение ToF-датчика на старом радиусе `28.0 мм` приводило к взаимному пересечению окон, что физически разрушало прочность крышки [enclosure_architecture_v7.md].
* **Инженерное решение (Конфигурация `false`):** 
  1. Датчик ToF VL53L5CX смещен по оси X на радиус **`X = +45.0 мм`** (координата `Y = 0.0 мм`) [enclosure_architecture_v7.md].
  2. Плата датчика развернута тангенциально (поперек оси X, длинной стороной вдоль оси Y) [enclosure_architecture_v7.md].
  3. Это обеспечивает гарантированный физический зазор между ферритом катушки и корпусом ToF-датчика в **0.75 мм** [enclosure_architecture_v7.md].
  4. Расстояние от ToF-датчика до аналоговых датчиков Холла (SS49E), расположенных на диагоналях 45°, увеличено до максимума [enclosure_architecture_v7.md]. Это защищает чувствительный аналоговый тракт Холлов от высокочастотных шумов цифровой шины I2C, гарантируя чистый сигнал и успешное прохождение теста селф-диагностики `BIST-HW-04` [bringup_test_suite_v6.md, quality-v9.md].

## 2. Реестр задач рефакторинга (Refactoring Backlog)

### TASK-RPI-4-REFACTOR: Математический сдвиг ПИД-контура сервера RPi 5
* **ID задачи:** `RPI-4-REFACTOR`
* **Компонент:** Управляющий сервер Raspberry Pi 5 (`main_server-v9.py`) [main_server-v9.py]
* **Технический стек:** Python 3.12, `asyncio`, FastAPI [main_server-v9.py, quality-v9.md]
* **Описание:** 
  Необходимо обновить глобальные константы смещения оптической оси ToF-датчика в управляющем ПО:
  ```python
  OFFSET_X_MM = 45.0
  OFFSET_Y_MM = 0.0
  ```
  Внутри главного асинхронного цикла левитации `core_loop_860hz()` при слиянии данных датчиков (Complementary Filter) [main_server-v9.py, quality-v9.md] формулы расчета декартовых координат сферы обязаны использовать новые значения смещения для компенсации геометрического сдвига:
  $$\text{absolute\_x} = \text{raw\_x} - \text{OFFSET\_X\_MM}$$
  $$\text{absolute\_y} = \text{raw\_y} - \text{OFFSET\_Y\_MM}$$
* **Критерии приемки (DoD):**
  - Сервер успешно инициализируется и запускает ПИД-контур на частоте 860 Гц [main_server-v9.py, quality-v9.md].
  - При смещении сферы по оси X на +10 мм, расчетная координата в телеметрии изменяется линейно и плавно без скачков и NaN-выбросов [main_server-v9.py, quality-v9.md].
  - Юнит-тесты `pytest` подтверждают корректность тригонометрического пересчета ПИД при значении `OFFSET_X_MM = 45.0` [quality-v9.md].

### TASK-EMC-GROUNDING: Аппаратное экранирование и защита (Hardware EMI Shielding)
* **ID задачи:** `EMC-GROUNDING`
* **Компонент:** Физическая сборка Базовой станции [base_power_assembly_guide-v5.md]
* **Технический стек:** Медный скотч, каптоновая лента, паяльные работы [enclosure_architecture_v7.md]
* **Описание:**
  Поскольку ToF-датчик работает на высокочастотных цифровых сигналах, необходимо выполнить следующие физические шаги при сборке по чертежу `enclosure_architecture_v7.md`:
  1. Обернуть шлейф подключения VL53L5CX (линии SDA, SCL, VCC, GND) в алюминиевую или медную фольгу, создав экранирующий рукав.
  2. Заземлить экранирующий рукав шлейфа ToF, припаяв его к общему полигону заземления «Звезда» (GND) силовой платы [base_power_assembly_guide-v5.md, enclosure_architecture_v7.md].
  3. Наклеить слой термостойкого каптонового скотча на плоскую перегородку-дефлектор внутри стакана [enclosure_architecture_v7.md], а поверх него нанести сплошной слой медного скотча, заземленный на GND [enclosure_architecture_v7.md]. Это защитит Raspberry Pi 5 от ЭМИ-излучения силовых ключей [enclosure_architecture_v7.md].
* **Критерии приемки (DoD):**
  - Физическая сборка завершена в соответствии с `enclosure_architecture_v7.md` [enclosure_architecture_v7.md].
  - Измеренный уровень шума силовой земли в тесте `BIST-HW-04` составляет строго **`RMS <= 8.4 мВ`**, что ниже критического порога безопасности в 12.0 мВ [bringup_test_suite_v6.md, main_server-v9.py].

## 2. ГЕОМЕТРИЧЕСКИЙ СТАНДАРТ (AXIAL COMPACT TOF ALIGNMENT)
Физический корпус Базы напечатан по модели `enclosure_architecture_v7.md` с параметром `tof_on_diagonal = false`. Это означает следующую жесткую физическую разметку сенсорной палубы крышки:
- Боковая катушка №2 (East) центрирована на оси X в координате `[27.0, 0]`. Её окно имеет радиус `11.5 мм` (занимает диапазон по оси X от +15.5 мм до +38.5 мм).
- Окно датчика ToF VL53L5CX смещено по оси X на координату **`X = +45.0 мм`**, `Y = 0.0 мм` и развернуто тангенциально (вдоль оси Y). 
- Это создает физический зазор между катушкой №2 и корпусом ToF-датчика в **0.75 мм** для предотвращения механических коллизий.
- Расстояние ToF до датчиков Холла (SS49E), расположенных на диагоналях на радиусе 15.5 мм, является максимальным. Это на 94% защищает аналоговый тракт Холлов от ВЧ-помех шины I2C при селф-тестах.

### Твоя задача (TASK-RPI-4):

- **`OFFSET_Y_MM = 0.0`**
Любые формулы слияния данных Complementary Filter в ПИД-контуре и калибровки Bring-up обязаны производить декартов пересчет относительно этого физического смещения!

## 3. ФИЗИЧЕСКИЕ И БЕЗОПАСНЫЕ ОГРАНИЧЕНИЯ (QoS SAFETY CONSTRAINTS)
Ты обязан аппаратно и программно зафиксировать в коде следующие неблокирующие барьеры безопасности:
1.  **Slew-Rate Limiter (Закон Ленца / di/dt Suppressor):** При любых условиях (даже при аварийном отключении или прыжках уставки) скорость изменения ШИМ на каждом из 5 каналов базы не может превышать `slew_rate_limit = 10` единиц за один асинхронный такт (1.16 мс / 860 Гц). Перепад ШИМ с 460 до 0 обязан плавно растягиваться не менее чем на **50 мс** для безопасного поглощения ЭДС самоиндукции диодами SS54 и TVS-зажимом SMBJ12A.
2.  **Силовой лимит ШИМ:** Жесткое программное ограничение скважности ШИМ базы на уровне **`460`** (из 10-бит / 1023) во избежание перегрузки блока питания 27W.
3.  **Бортовой Software Fuse Агента:** Защитная отсечка ШИМ катушки сферы при непрерывной подаче тока свыше **`500 мс`** на мощности >30%, если крен сферы превышает 0.5°.
4.  **Двухфазный интерлок реле Агента:** Размыкание нормально-замкнутого реле CPC1017N строго за **`RELAY_SETTLE_MS = 5.0 мс`** до подачи импульса в бортовую катушку.

## 4. РЕАЛИЗАЦИЯ СЦЕНАРИЕВ, ДИАГНОСТИКИ И ВЫКЛЮЧЕНИЯ (BIST & SHUTDOWN)

- **Retry и Bypass:** Обеспечь работоспособность эндпоинтов `/api/bist/retry` (для повторного точечного запуска тестов) и `/api/bist/bypass` (для двухфакторной разблокировки с соглашением пользователя).
- **Safe Shutdown (Сценарий UC-9):** Плавный спуск сферы (5.0 мм/с) за 5 секунд, рамп-даун ШИМ катушек базы за 2.0 секунды, отправка команды STANDBY Агенту и переход интерфейса в режим глубокой блокировки с неоновым баннером «SAFE TO UNPLUG 27W».
